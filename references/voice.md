# 文案规则：怎么写不像 AI 写的

简历里的 AI 味不在用词，在**说话的姿态**。下面每条都来自真实的修改记录。

## 一、元陈述式标签句（最该删的一类）

先给自己的做法贴一个抽象标签，再举例证明这个标签。

```
✗ 产品判断写在作品里：心理效应档案首屏不给定义……
✗ 对 AI 产品形态是动手理解的：6 个公开 Agent 技能包……
✗ 端到端一人闭环：定义问题 → 技术选型 → 实现……
```

**为什么假：**正常人直接讲事，不会先宣布「接下来我要展示我的判断力」。这类句子不传达信息，它在告诉读者该怎么评价接下来的信息——那是表演。

**改法：**删掉标签句，直接说事。

```
✓ 心理效应档案首屏不给定义，先让用户转一次转盘亲手栽进锚定效应
```

## 二、标签要客观分类，不要自我评价

同样是「标签：内容」，性质完全相反。

```
✓ 提升留存：重做新手引导，次留 +1.91%、七留 +1.86%
✓ A/B 测试：plist 远程配置，从 3 个对比组中选出最优方案
✓ 法律合规：设计满足 AppTrackingTransparency 与 GDPR 的功能

✗ 产品判断：待办清单只回答「有什么要做」……
✗ 核心优势：独立开发 11 款产品……
```

前三个说明**这条讲什么**，读者靠它扫描定位。后两个说明**我多厉害**。

## 三、不揣摩用户心理

```
✗ 逼用户当场判断重要／紧急，这点摩擦足以让他干脆不记
✗ 栽过一次再讲道理
✗ 因为用户往往只记得「那个念 mai pen rai 的」
✗ 列表会让人误以为「看过了就是记住了」
```

**改法：**只写做了什么、结果是什么。

```
✓ 加收集箱功能，录入时不要求分类，先录入再归象限
✓ 搜索同时匹配中文、泰文、发音三者。复习功能做成翻卡片，不做列表
```

## 四、小标题用实词

```
✗ 它怎么工作 / 为什么做成纯前端 / 你只给两样 / 四步全自动
✓ 输入 / 分镜 / 出片 / 技术 / 录制 / 剪辑 / 导出 / 搜索和筛选
```

自问自答式、第二人称卖点式、营销腔，三种都不要。

## 五、中文里不要第二人称

英文技术写作里 `you` 是自然的（同一批作品的英文版用了 5–13 次都不违和），中文里「你」会立刻显出翻译腔和营销腔。

```
✗ API Key 填在你自己的浏览器里，费用走你自己的账户
✓ API Key 存在浏览器里，费用记在填 key 的那个账户上
```

## 六、正面的写法

**数字具体，不取整。** 次留 1.91%、七留 1.86%、80 万条数据、1600 余支队伍、全国第 22 名、4h11m。一条 bullet 里常有两三个数。

**先写背景和动机，再写做了什么。**

```
✓ 当时小程序发展迅猛，对手机应用商店 DAU 造成威胁；主站 DAU 增长遇到瓶颈，急需探求新的流量增长点
```

**直说抄谁，不包装。**

```
✓ 对标微信小程序品牌商城
✓ 参考同类音频产品的「每天听本书」设计读书会项目；参考三款打卡类 APP 设计签到功能
```

**专有名词原样写，不缩写不翻译。** AppTrackingTransparency（不是 ATT）、GDPR、Rating Alert、Facebook deeplink、CPI、plist、ScreenCaptureKit。

**流程用连字符串成一串。**

```
✓ 需求分析-产品文档-设计-开发-埋点-测试-灰度-上线-数据
```

**不修饰不抒情。** 陈述事实和结果，不要转折升华。

## 七、量化自检

跑 `deslop-zh` 技能的脚本拿超标清单：

```bash
python3 ~/.claude/skills/deslop-zh/scripts/check.py <文件> --verbose
```

**但阈值要按作者的基线校准，不是照搬。** 实测某作者自己写的六篇文章，破折号密度在 2.4–7.0/千字，全部「超标」——那是他的语气，不是毛病。段落长度标准差同理。

脚本查不出元陈述式标签句和小标题的说话方式，那两样只能靠人读。
