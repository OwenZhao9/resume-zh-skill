# 协作流程：怎么不把用户的修改弄丢

**这份是这个 skill 里最重要的。** 下面三个坑我全踩过，每次都抹掉了用户几十分钟的修改，而且恢复不了。

## 文件关系

```
简历-LaTeX.html      静态源文件，agent 改这个
简历-可编辑.html      ← 用户在浏览器里改的就是它，权威版本
简历.tex             LaTeX 版
简历.pdf             成品
_backups/            每次保存前的时间戳快照
```

`-可编辑.html` 由 `make_editable.py` 从源文件生成，注入 `contenteditable` 和保存脚本。**一旦用户开始编辑，它就跟源文件分叉了，此后它才是权威。**

## 坑一：清 localStorage

早期版本把编辑存在 localStorage。agent 改完文件后为了让文件版生效，执行了：

```js
localStorage.removeItem(KEY); location.reload();   // ← 绝对不要
```

这一步把用户手动删的小标题、改的产品名全冲掉了，连做了八九次。

**根治：改成直接写文件**（见 `scripts/server.py`），不再有 localStorage 这个中间层。

## 坑二：重新生成整个可编辑文件

```bash
python3 make_editable.py     # ← 用户已经开始编辑之后，绝对不要再跑
```

它从源文件整份覆盖 `-可编辑.html`，只存在于可编辑版里的改动全没。

**改动已开始之后，直接对 `-可编辑.html` 做定点替换，不要重新生成。**

## 坑三：页面把 agent 的改动盖回去

保存时页面把整个 `<body>` 写回文件。用户那个标签页里还是旧 DOM，任何一次触发保存就覆盖掉 agent 刚写进去的内容。

**根治：版本校验。** 服务端返回 HTML 时注入文件 mtime：

```html
<meta name="file-version" content="1788599656559">
```

页面保存时带回来比对，不一致就返回 409、页面弹红条提示刷新，而不是静默覆盖。

注意：**从旧备份还原文件时，会连带把旧版保存脚本一起还原**，版本校验就没了。还原后要重新注入脚本。

## 正确的流程

**Agent 要改文件时：**

1. 先读页面当前状态（`document.body.innerHTML` 或按区块取 `textContent`），把用户的改动抄进来
2. 对 `-可编辑.html` 做**定点替换**，不重新生成
3. 改完**不要替用户刷新**。告诉他文件已更新、他那边刷新会丢未保存的改动
4. 重新导出 PDF，`git commit`

**要拿用户最新版时：**让他 `Cmd + S`，或直接读文件（存盘服务保证文件就是最新的）。

**每一步都 git commit。** 这个目录应该是 git 仓库，出事能 `git checkout` 回滚。备份目录 `_backups/` 不入库（近乎重复、体积大，git 历史已经起同样作用）。

## 检查清单

改完一轮，按顺序过：

1. `python3 scripts/check.py 简历-可编辑.html` —— 空格、句末标点、链接
2. 导出 PDF，确认还是一页
3. 扫 PDF 二进制确认链接真的嵌进去了
4. 时间线：各段起止是否重叠、是否有解释不了的空档
5. 数字一致性：同一个东西在不同地方是不是同一个数（「11 款」vs「12 款」这种最伤）
6. `git commit`

第 4、5 条脚本查不了，得人读。实测漏过一次：11 款和 12 款在同一页出现，扫格式时没发现。
